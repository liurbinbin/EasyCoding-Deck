# 语音面板维护说明

实时对话卡片明确展示「正在停止」与「设备停止待确认」。旧连接退役后原生层结束本地会话，不伪装取得设备空闲回执；同一连接尚未确认停止时仍禁止新会话抢占。

S3WifiPanel 只通过 DeviceContext 调用本地 Tauri intent：USB 配网、设备网络状态、mDNS 候选、手动 WSS endpoint、认证连接和忘记配对。面板轮询并显示 configured、SSID、IP、RSSI、WSS client/challenge 与 authenticated 状态；前端不得创建 WebSocket、保存密码/pair secret，或把发现结果当作已认证身份。

豆包不再作为桌面 Agent 渠道展示或接收设备语音路由；豆包模型、ASR/TTS 与生成服务仍属于独立 API 配置。

Agent 与形象矩阵区分“已安装”和“状态通道可用”：OpenCode 可通过托管插件跟随；Hermes Agent/ZCode 在仅检测到应用但没有可验证 Hook 时显示“待适配”，不得启用跟随或形象切换。形象名称属于用户数据，使用 `data-locale-ignore` 避免与界面词库命中时被翻译；状态、按键说明与操作标签继续跟随界面语言。

SerialLogPage 是主导航中的全页日志视图，读取 Tauri 已持有串口的有界内存日志，提供实时 RX/TX、可选跟随最新、暂停、复制和清空；日志区独立滚动并在布局完成后跟随底部，操作栏固定在页面底部；不得从前端另开 Web Serial 端口。
DashboardActionsMenu 不再重复提供串口日志入口，S3 诊断入口显示为 ESP32-S3 设备诊断。
S3HardwarePanel 显示 T-Keyboard Voice 的五块非触摸按键屏、ES7210/ES8389、电源遥测和扩展接口边界；BoardButtonPanel 为 S3 只显示五个带屏按键，K4 长按固定为 2–10 秒可配置的深睡眠，不显示旋钮。
BoardButtonPanel 将短按确认/返回作为唯一物理映射；把确认改到 K2 时会解除旧确认键，普通动作仍允许重复绑定。K4 长按可选择 AXP2101 关机断电或 ESP32 深度休眠，并独立保存 2–10 秒触发时长。
useP4SessionSync 忽略设备标记为 handledLocally 的输入，防止审批确认等板端模态操作再次触发会话切换绑定。
T-Keyboard Voice 的“宠物／组件切换”在 S3 上显示并执行为当前宠物动作循环；K5 默认触发，Agent 新状态到达后恢复自动状态动画。

2026-10-24：实时对话的单轮 ASR 超时显示继续聆听提示，不显示「实时对话失败」或要求重新开始；其他错误仍保留。新增 lib/realtime-feedback.js 判定测试。

Mac 语音候选修复待真实录音验收。
VoiceAssistantPanel 使用 deviceVoiceTransportReady 区分原生桌面草稿与CLI就绪状态，
Mac Codex 不因 CLI 缺失禁用启动；权限、窗口和真实输入检查仍由原生通道负责。
VoiceComposerCheck 展示用户触发的脱敏文本区明细，不自动录音或写入。

Voice runtime polling now waits for a completed known USB target, binds asynchronous results to device/channel identity and uses native ASR for the negotiated device runtime. Credential configuration is distinct from runtime running; stale legacy results cannot replace current UI state.

2026-11-03：首页语音输入下方使用 DeviceVolumePanel（设备确认后显示音量，未知设置结果先只读核对）与 SharedLocationPanel（自动识别/手动地区）；设置页保留服务配置。位置正常布局至多三行，不显示经纬度；手动输入城市、区县时以防抖联想展示真实候选及父级地区，选择后显式保存。切换页面、输入法组合、旧异步响应与保存期间均隔离候选。位置不写入包内资源。
2026-11-09：DeviceVolumePanel 对声明能力的 T-Keyboard Voice 开放持久化总音量，并提供最长 15 秒的 WAV 转换、精确设备绑定播放和停止；形象音效同步由独立能力控制。

Follow/appearance cancellation describes only the stopped request; it does not promise the device kept the old image. Unknown native appearance codes are replaced by a short failure notice, never a success notice or automatic resend.

ChannelMatrix has no separate appearance-reconciliation button. A new confirmed follow request briefly shows confirmation while its own read-only preflight checks any old unknown transfer; only successful proof/no-pending permits that request's fresh once-only switch. No old mutation is resumed and no action is dispatched from a failure catch. Required-firmware and incomplete-proof failures remain visible; DeviceContext owns cancellation and USB board/generation/boot continuity.
The follow modal's "keep current appearance" choice is authoritative: it changes the Agent binding and mapping without appearance reconciliation, progress listeners, or `usb_sync_appearance` asset transfer.

设备操作菜单和固件选择对话框使用通用、简洁的操作名称；可见产品名称统一为 EasyCoding Deck，不改变 capability 门控和后端镜像验证。
