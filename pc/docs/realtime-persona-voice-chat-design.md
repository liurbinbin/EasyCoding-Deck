# EasyCoding Deck 人设与声音架构

形象的人设与音色由桌面端管理，实时对话通过设备采集、电脑端识别与模型服务、设备播放组成完整链路。使用步骤和排查见 [实时对话](realtime-chat.md)。

## 模块分工

| 模块 | 职责 |
| --- | --- |
| `pc/src/PersonaVoiceModal.jsx` | 人设、音色、语速、试听和保存 |
| `pc/src/lib/persona-voice.js` | 组装启动参数与声音配置 |
| `pc/src/shell/DeviceContext.jsx` | 将当前形象与精确设备身份交给原生层 |
| `pc/src-tauri/src/realtime_chat.rs` | 会话、ASR、模型、工具、TTS 与音频生命周期 |
| `pc/src-tauri/src/voice_chat_settings.rs` | 对话服务配置与安全存储边界 |
| `firmware-s3/src/audio_service.cpp` | 半双工采集、播放、有界缓冲与设备回执 |
| `firmware-s3/src/board_runtime.cpp` | 形象动画、交互状态和字幕显示 |

表中的路径均相对于仓库根目录。

## 配置与启动

人设和音色、语速按形象保存，对话音量独立保存为全局设置。新会话读取当前配置，活动会话更新作用于后续回复，不覆盖用户保存的自定义内容。

启动请求包含形象、显示名、人设、开场内容、声音配置与精确 `boardDeviceId`。原生层核对实际连接和 capability，再持有当前会话与音频写入归属。

试听由原生端执行，试听成功不替代设备音频链路或实际声学验收。

## 半双工会话

```text
准备 → 收音与识别 → 模型决策 → 合成与播放 → 收音与识别
  └──────────────── 用户结束 / 超时 / 连接退役 ───────────────┘
```

回复播放期间暂停采集，设备实际播放完成后恢复收音。准备、处理中、正在播放、正在停止和停止待确认分别显示，不将请求已发送当成业务已完成。

## 工具与权限

模型可以调用明确注册的工具，但不能通过回复文本扩大权限。家居、待办、状态、联网查询和桌面任务分别校验参数、目标和确认条件。

任务查询与写入回执分开处理；超时、取消或结果未知不自动重放。外部网页与工具结果只作为数据，不构成授权指令。

## 连接与隐私

USB/WSS 共用设备身份、generation、writer 与 waiter。断线或切换连接终止旧录音、播放和待确认操作，迟到回执不能控制新连接。

服务凭据留在电脑安全存储中，不下发到设备。诊断只记录固定阶段、计数、耗时与错误类别，不保存录音、完整对话或密钥。

## 验证

参数组装、配置投影、连接归属和停止语义由 Node/Rust 契约测试覆盖；固件构建、设备采播、长回复、字幕同步、功耗与声学分别验证。构建或回执通过不能替代实机结果。
