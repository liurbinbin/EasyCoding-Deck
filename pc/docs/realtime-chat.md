# EasyCoding Deck 实时对话

实时对话让用户直接与当前形象交谈。它与按键语音输入是两条独立路径：按键语音写入 Agent 草稿，实时对话由电脑端完成识别、模型请求和语音合成，再将回复播放到设备。

## 开始使用

1. 在设置中配置语音识别、语音合成和对话模型所需的账号与凭据。
2. 在形象页面打开「人设与声音」，选择音色、语速和人设并保存。
3. 连接设备后，使用配置为「实时对话」的快捷键或客户端开始按钮进入对话。默认快捷键为 K5 长按。
4. 等待准备完成后说话。设备播报回复时暂停收音，播放结束后恢复。
5. 再次触发快捷键或点击结束按钮停止对话。

设备保存的按键配置优先。普通 Agent 语音输入、草稿确认与工具审批不因此自动开启。

## 原生链路

```text
设备麦克风
    │ 16 kHz 单声道 PCM16
    ▼
USB CDC / 认证 WSS
    ▼
Rust：流式 ASR → 对话模型与受控工具 → 流式 TTS
    ▼
同一设备连接 → 有界播放缓冲 → ES8389 扬声器
```

Rust 持有对话会话、连接代次、音频 writer 和回执。设备负责采集、字幕与播放；不直接访问云端模型，不运行 Python sidecar 或外部 RTC 服务。

当前设备采用半双工模式。播报时暂停采集，避免扬声器声音进入下一轮识别；不要将说话打断播放视为当前设备已支持的操作。

## 字幕与状态

屏幕 3 显示识别反馈与当前回复。回复句子在播放前通过 `ui/conversation` 下发，并按设备播放进度更新字幕。准备、处理、网络查询和失败也通过同一状态链路反馈。

`asr_final` 只表示识别完成，模型响应、工具执行与设备播放是后续独立阶段。成功发送音频不代表扬声器已经播放；实际结束以设备 `playback_completed` 为准。

客户端等待窗口依据实际 PCM 时长并附加有界传输余量。结束按钮先显示「正在停止」；未取得同一连接的真实停止回执时显示「设备停止待确认」，不让新会话抢占。

## 人设、声音和音量

- 人设、音色与语速按形象保存；自定义设置不因切换默认值而被覆盖。
- 对话音量为全局设置，切换形象不改变该值。
- 新会话重新读取已保存配置。活动会话的参数更新作用于后续回复，不重放已经开始的声音。
- 已发送到设备缓冲中的音频不会因客户端修改音量而即时改变。

服务可用性受账号权限、模型和音色支持情况影响。资源或音色不匹配时先修正配置，不重复提交相同失败请求。

## 工具与确认

对话可使用当前允许的家居、待办、电脑状态、联网查询或桌面任务工具。工具开放、参数、ID、版本和账号权限分别核验，口头回复不代替执行回执。

- 需要确认的任务只接受当前对话内的有效确认，取消、修改请求、退出或过期后失效。
- 查询成功与写入成功分开表述；已经尝试执行或结果未知的操作不自动重放。
- 目标窗口、会话或设备身份变化时停止当前操作，不自行选择历史会话。
- 联网内容和工具返回值作为不可信数据，不构成新的操作授权。

桌面任务的权限与上下文边界见 [desktop-agent-voice.md](desktop-agent-voice.md)。

## USB / Wi-Fi 生命周期

USB 使用 JSONL/base64，Wi-Fi 使用认证 WSS text/base64。两种链路共享精确设备身份、connection generation 和音频会话归属。

音频以有界小块发送并等待对应回执，设备由独立音频任务消费缓冲；控制消息和停止操作不应被大块音频长期阻塞。

切换连接、断线或 generation 变化会终止旧对话。旧回执不影响新连接，也不向新连接发送旧会话的清理命令。结束本地会话不等于已证明旧设备处于空闲状态。

普通音频回执超时会停止当前轮次，不重发结果未知的播放块。暂时背压仅在确认尚未入队时保留当前待发送帧。

## 排查

| 现象 | 检查项 |
| --- | --- |
| 无法开始 | 设备连接、当前形象、人设与声音、语音和模型凭据 |
| 识别完成但没有回复 | 模型权限、接口配置、请求耗时和工具决策结果 |
| Wi-Fi 下中断 | 网络互通、认证状态、连接 generation、收发队列与回执 |
| 字幕正常但没有声音 | 设备音量、播放状态、缓冲计数与实际播放完成事件 |
| 停止后不能开始 | 是否仍处于停止待确认；先核对同一连接的实际状态 |
| TLS 验证失败 | 系统时间、可信证书和已保存代理；不要关闭校验 |

单轮识别超时会丢弃未完成识别与等待音频，不派发部分指令或重放录音。鉴权、额度和配置错误应修正后再由用户发起新请求。

## 日志与隐私

PC 日志位于应用数据目录的 `logs/realtime-chat.jsonl`，达到 1 MiB 后轮转。记录固定阶段、耗时、状态、字符/字节计数与错误类别，不记录密钥、完整提示词、对话正文或 PCM。

设备通过 `audio/diagnostic` 上报播放、缓冲、时钟及错误元数据；驱动时钟记录不是物理测量。网络稳定性、实际播放、频率偏差、功耗和声学效果需要分别完成实机验收。
